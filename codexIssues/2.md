# Iteration 2.11 — Maven Test Runner (Codex Task)

## Goal

Implement a deterministic Maven test runner with two-phase execution:

- `VERIFY_TARGET` — fast execution of only the generated test (class or method)
- `FULL_SUITE_COVERAGE` — full test suite execution with verification of JaCoCo XML presence  
  (path is already known from configuration/detector; runner does **not** configure it)

---

## Scope (What to Do)

### 1) Contracts (Domain Types)

Create/add the following entities (use project conventions for packages, but avoid over-engineering):

#### Enums

java enum TestRunMode { VERIFY_TARGET, FULL_SUITE_COVERAGE }

java enum TestFailureType { COMPILATION_FAILURE, TEST_FAILURE, INFRA_FAILURE }


#### Value Objects

**`TestTarget`**
- `String className` (required)
- `String methodName` (nullable)

**Invariant:** `methodName` may only be present if `className` is set.

---

**`TestRunRequest`**
- `TestRunMode mode`
- `TestTarget target` (required only for `VERIFY_TARGET`, `null` for `FULL_SUITE_COVERAGE`)
- `Path projectRoot`
- `Duration timeout`
- `Map<String, String> env` (optional)
- `List<String> mavenArgsExtra` (optional, for future extensions)

---

**`TestRunResult`**
- `boolean success`
- `int exitCode`
- `Duration duration`
- `String stdout` (size limit allowed but not required)
- `String stderr`
- `Optional<TestFailureType> failureType` (if `success == false`)
- `Optional<String> failureSummary` (short summary: 1–3 lines)

---

### 2) Runner Abstraction

**Interface:**

java interface TestRunner { TestRunResult run(TestRunRequest request); }

**Implementation:**

java class MavenTestRunner implements TestRunner

---

### 3) Maven Commands (Required Behavior)

#### `VERIFY_TARGET`

Execute only the specified test (class or method) using Surefire/Failsafe:

- Class: `-Dtest=ClassName`
- Method: `-Dtest=ClassName#methodName`

**Base command:**

bash mvn -q -Dtest=... test

> `-q` is optional but recommended by default (reduces noise).

---

#### `FULL_SUITE_COVERAGE`

Run full test suite:

bash mvn -q test

After execution (only if `exitCode == 0`), verify that JaCoCo XML exists at the known path (passed via request or obtained via simple `CoveragePathsProvider` — choose simpler option, no magic).

> ❌ **Hard error:** If JaCoCo XML is missing → `INFRA_FAILURE`, even if tests passed.

> ⚠️ **Non-goal:** No auto-attachment of JaCoCo, no `pom.xml` modifications, profiles, etc.

---

### 4) Process Execution (How to Run)

Use `ProcessBuilder`:

- `directory = projectRoot.toFile()`
- Capture `stdout`/`stderr` (preferably via separate threads to avoid blocking)
- Measure `duration`
- Enforce `timeout` → on timeout: `INFRA_FAILURE`, `exitCode = -1`

**Determinism requirements:**
- Fixed list of arguments
- No parallelism / randomness
- No guessing of profiles or build variants

---

### 5) Error Classification (Mandatory)

Classify failures based on `exitCode != 0` and output content:

#### `COMPILATION_FAILURE`
**Indicators (simple heuristics):**
- `COMPILATION ERROR`
- `Compilation failure`
- `Failed to execute goal ... maven-compiler-plugin`

#### `TEST_FAILURE`
**Indicators:**
- `Tests run:`
- `There are test failures`
- `Failed tests:`
- `Error(s):`

#### `INFRA_FAILURE`
All other cases, including:
- `Could not resolve dependencies`
- `No such file or directory`
- Timeout
- Missing JaCoCo XML after `FULL_SUITE_COVERAGE`

> ✅ Classification must be predictable, **not** "smart".

---

## Acceptance Criteria (Definition of Done)

✅ `MavenTestRunner` supports both modes.

✅ `VERIFY_TARGET` runs only the specified target via `-Dtest=...`.

✅ `FULL_SUITE_COVERAGE` verifies existence of JaCoCo XML after success; fails with `INFRA_FAILURE` if missing.

✅ Returns `TestRunResult` with correct `duration`, `exitCode`, `stdout`, `stderr`.

✅ Errors are classified into one of the three types.

✅ Runner does **not** modify build configs or production code.

✅ Unit tests included for:
- Command assembly for class-only and class#method
- Error classification using sample output (no real `mvn test` execution)
- Missing `jacoco.xml` → `INFRA_FAILURE`

## Notes (Important Constraints)

🚫 Do **not** add dependencies.  
🚫 No integration tests that actually run `mvn test`.  
🚫 No "smart" detection of JaCoCo path: runner receives path from outside or via minimal provider interface.
