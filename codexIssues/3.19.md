## Iteration 3 — Structured Output Validation (Codex Task)

Goal:
Design and formalize **strict structured output validation** for LLM test generation in TestSmith, ensuring deterministic, production-safe integration.

Scope:

* Define canonical structured output schema
* Define validation pipeline
* Define failure modes
* Define retry policy
* Define invariants
* No UI work
* No execution logic changes
* No build modification

Open questions:

* JSON vs DSL?
* Single test per response vs batch?
* Strict parser vs tolerant parser?
* Where to enforce schema: LlmClient layer or Agent layer?

---

# 1️⃣ Architectural Positioning

Structured output validation sits **between LLM and Agent Loop**.

```text
LLM → Raw Response → Structured Parser → Validator → Agent Loop
```

Invariant:
**Agent never operates on raw LLM text. Only validated structured objects.**

This follows RFC safety principles .

---

# 2️⃣ Why Structured Output Is Mandatory

Without structure:

* hallucinated imports pass silently
* missing metadata not detected
* unsafe file writes possible
* retry logic impossible to formalize
* manual mode diff unreliable

Structured contract ensures:

* deterministic parsing
* invariant enforcement
* safe retries
* failure classification
* test execution isolation (Iteration 2.11 / 2.12 alignment)

---

# 3️⃣ Canonical Response Schema (v1)

We use **strict JSON schema**.

### Top-level contract

```json
{
  "version": "1.0",
  "action": "GENERATE_TEST" | "FIX_TEST",
  "targetClass": "com.example.MyService",
  "testClassName": "MyServiceTest",
  "imports": ["org.junit.jupiter.api.Test"],
  "code": "public class MyServiceTest { ... }",
  "assumptions": [],
  "requiresInfrastructure": false
}
```

---

# 4️⃣ Schema Invariants

Mandatory:

* version == "1.0"
* action present
* targetClass matches requested
* testClassName ends with Test
* code contains class declaration with matching name
* no markdown
* no explanations
* no surrounding prose
* valid JSON only

Forbidden:

* imaginary classes in assumptions
* infrastructure creation
* build changes
* modifying production files

If violated → **BLOCKER**

---

# 5️⃣ Validation Pipeline

## Step 1 — JSON Parsing

Failure → `STRUCTURE_INVALID`

## Step 2 — Schema Validation

Missing fields → `SCHEMA_INVALID`

## Step 3 — Semantic Validation

* testClassName matches class in code
* targetClass matches requested
* no prohibited annotations (e.g. @SpringBootTest unless discovered)
* no invented base classes

Failure → `SEMANTIC_INVALID`

## Step 4 — Infrastructure Validation

If requiresInfrastructure == true → BLOCKER
(Iteration 3 does not support infra creation)

# 6️⃣ Java Contract

```java
public interface StructuredResponseParser {
    StructuredTest parse(String raw);
}
```

```java
public interface StructuredValidator {
    ValidationResult validate(StructuredTest test, GenerationContext context);
}
```

```java
public record ValidationResult(
        boolean valid,
        ValidationErrorType errorType,
        String message
) {}
```

```java
public enum ValidationErrorType {
    STRUCTURE_INVALID,
    SCHEMA_INVALID,
    SEMANTIC_INVALID,
    INFRASTRUCTURE_REQUIRED
}
```

---

# 7️⃣ Retry Strategy

Deterministic.

| Error Type              | Retry? | Strategy                            |
| ----------------------- | ------ | ----------------------------------- |
| STRUCTURE_INVALID       | Yes    | Re-prompt with stricter instruction |
| SCHEMA_INVALID          | Yes    | Inject schema example               |
| SEMANTIC_INVALID        | Yes    | Provide violation explanation       |
| INFRASTRUCTURE_REQUIRED | No     | Abort                               |

Max retries: 2

After max retries → Abort iteration.

---

# 8️⃣ Prompt Contract (Critical)

LLM must receive:

* Strict JSON schema
* Explicit instruction:

    * No prose
    * No markdown
    * JSON only
* Failure example
* Valid example

Temperature = 0.1
Determinism required per RFC .

---

# 9️⃣ Single vs Batch Decision

Iteration 3 decision:

**Single test per generation**

Reasons:

* simpler validation
* simpler retry
* isolated execution (VERIFY_TARGET)
* aligned with two-phase runner
* easier diff review in Manual Mode

Batch generation deferred.

---

# 🔟 Enforcement Layer

Validation must live in:

Agent layer, not LlmClient.

Reason:

LlmClient = transport abstraction
Agent = domain authority

This preserves multi-LLM support in Iteration 5.

---

# 1️⃣1️⃣ Failure Mode Matrix

| Failure          | Agent Behavior |
| ---------------- | -------------- |
| Parse fail       | Retry          |
| Schema fail      | Retry          |
| Semantic fail    | Retry          |
| Infra required   | Stop           |
| Compilation fail | Fix cycle      |
| Test fail        | Fix cycle      |

---

# 1️⃣2️⃣ Hard Safety Invariants

* No file writes before validation passes
* No execution before validation passes
* No coverage update before FULL_SUITE_COVERAGE
* Structured response required even in FIX mode
* Raw LLM text never logged without sanitization
